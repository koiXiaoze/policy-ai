# 政府站点连续可用性验收台账

本台账用于验收 `config.yaml` 中 **5 个固定启用来源**的每日运行可用性。验收对象为：

1. 国务院
2. 湖北省人民政府
3. 武汉市人民政府
4. 十堰市人民政府
5. 人力资源和社会保障部

## 验收规则

- 只有 GitHub Actions 的 `event=schedule` 运行计入连续窗口。
- 每个北京时间自然日至少有一次定时运行成功。
- 当天运行的 5 个来源名称必须与固定清单完全一致、无缺失、无重复、无新增。
- 每个来源必须满足：`status=ok`、`fetch_status=ok`、列表数大于 0、`content_status=ok`，且首条正文不少于 100 字符。
- 采集器标准输出、标准错误和应用日志必须通过脱敏扫描：禁止出现来源 URL、明文凭据、正文和请求头；仅允许 Runner 基础设施 URL、Artifact 下载链接及脱敏后的 `token: ***` 等安全内容。
- 任一天失败、没有记录、Artifact 缺失、来源不完整或验证器失败，连续计数重置。
- 手动 `workflow_dispatch` 运行可作为功能验证，但不计入 14 天窗口。
- 不得预填尚未发生的通过结果，也不得用列表数或结构探针摘要替代真实 canary。

## 每日核对方式

1. 确认工作流运行事件为 `schedule`，并记录 Run ID。
2. 下载或读取该 Run 的 Artifact，记录 Artifact ID。
3. 核对 Manifest 的 `status=ok`、`beijing_date` 与当天日期一致、`source_count=5`，且来源名称与固定清单完全一致。
4. 记录 5 个来源的 `item_count` 与 `content_chars`。
5. 确认 Run 的公开日志没有来源 URL、凭据或正文；校验器失败时只记录模式类别，不记录命中内容。
6. 任一项不符合时，将当天结果记为失败并重置连续计数。

## 自动化门禁与异常语义

- `Government Source Canary` 每日 00:17 UTC（北京时间 08:17）运行，固定验证当前 `config.yaml` 中启用的 5 个来源。
- `Public Release Gate` 每日 01:17 UTC（北京时间 09:17）运行，审计截至昨日的 14 天窗口、最终提交及全部 `origin` Ref。
- 两个审计脚本的退出码统一为：`0` 完整通过；`1` 证据不足或安全失败；`2` API、格式、网络或报告写入异常。
- Canary 审计的 `earliest_release_date` 仅在完整的 14 天窗口全部通过时返回该窗口结束日；证据为空或不足时返回 `null`，不得把缺失日期外推为未来通过记录。
- 验收范围仅为当前 `config.yaml` 的 5 个启用来源；停用来源、配置外政府站点和未来站点改版不在既有证据的可用性承诺内。
- 截至 2026-11-13，连续窗口为 **0/14**，仓库必须保持 **Private**；不得预填 2026-11-14 至 2026-11-27 的未来通过记录。
- 手动 `workflow_dispatch` 仅用于功能验证，不计入 14 天连续窗口。
