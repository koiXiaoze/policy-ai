# 政府站点发布后可用性巡检台账

本台账用于记录 `config.yaml` 中 **5 个固定启用来源**的发布后可用性趋势。巡检对象为：

1. 国务院
2. 湖北省人民政府
3. 武汉市人民政府
4. 十堰市人民政府
5. 人力资源和社会保障部

## 发布边界

- 发布前以最终发布提交上的三项证据为准：Release Smoke Check 成功、手动触发 `Government Source Canary` 的 5 个来源全部通过、全历史公开发布安全审计通过。
- 手动 `workflow_dispatch` 的 Canary 结果用于发布前功能验证，必须核对 Run、Artifact 和 5/5 来源结果。
- 14 天滚动统计是发布后的质量趋势指标， **不是发布日期门禁**，不得因窗口尚未满 14 天阻塞已经通过发布审计的版本。
- 单次或短期通过只能证明对应时点的链路有效，不能承诺外部政府网站永久不改版、不触发 WAF 或不发生网络中断。

## 验收口径

- 每个北京时间自然日至少有一次定时 `event=schedule` 运行成功，才计入当日趋势。
- 当天运行的 5 个来源名称必须与固定清单完全一致、无缺失、无重复、无新增。
- 每个来源必须满足：`status=ok`、`fetch_status=ok`、列表数大于 0、`content_status=ok`，且首条正文不少于 100 字符。
- 采集器标准输出、标准错误和应用日志必须通过脱敏扫描：禁止出现来源 URL、明文凭据、正文和请求头；只允许 Runner 基础设施 URL、Artifact 下载链接及脱敏后的安全内容。
- 任一天失败、没有记录、Artifact 缺失、来源不完整或验证器失败，应在台账中如实记录并触发修复；不预填尚未发生的通过结果。

## 发布后趋势

- `audit_canary_history.py` 以 14 个北京时间自然日为滚动窗口，只统计 `event=schedule` 的成功记录。
- 发布工作流中的趋势审计失败只表示样本不足或近期巡检异常，不自动撤销已发布版本，也不应把已发布仓库重新切回 Private。
- 若定时 Canary 出现真实失败，应检查 Workflow Run、脱敏 Artifact 和对应来源变化，修复后重新发布或更新部署；真实安全事件另按安全响应流程处理。
- 该趋势用于观察近期质量，不等同于生产 SLA 或永久可用性证明。

## 每日核对方式

1. 确认工作流运行事件为 `schedule`，记录 Run ID。
2. 下载或读取该 Run 的 Artifact，记录 Artifact ID。
3. 核对 Manifest 的 `status=ok`、`beijing_date` 与当天日期一致、`source_count=5`，且来源名称与固定清单完全一致。
4. 记录 5 个来源的 `item_count` 与 `content_chars`。
5. 确认 Run 的公开日志没有来源 URL、凭据或正文；校验器失败时只记录模式类别，不记录命中内容。

## 自动化与异常语义

- `Government Source Canary` 每日 00:17 UTC（北京时间 08:17）运行，固定验证当前 `config.yaml` 中启用的 5 个来源；发布前也可手动运行。
- `Public Release Safety Audit` 每日 01:17 UTC（北京时间 09:17）生成 14 天滚动趋势，并审计最终提交及全部 `origin` Ref。趋势步骤不阻断，历史安全审计步骤阻断。
- `audit_canary_history.py` 的退出码为：`0` 窗口完整通过；`1` 证据不足或近期巡检失败；`2` API、格式、网络或报告写入异常。工作流将该脚本作为非阻断趋势步骤运行。
- `audit_public_release.py` 的退出码为：`0` 安全审计通过；`1` 安全门禁失败；`2` API、格式、网络或报告写入异常。该脚本是公开发布的唯一自动安全阻断项。
- 巡检范围仅为当前 `config.yaml` 的 5 个启用来源；停用来源、配置外政府站点和未来新增站点不在既有证据的可用性承诺内。
